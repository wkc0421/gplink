MQTT 客户端配置说明

这份说明面向第一次接入外部 MQTT Broker 的用户。按页面从上到下完成网络组件、接入网关、产品和设备配置，最后再验证启用状态。

本页目录 开始前准备 四步配置 保存与验证 常见问题

先理解这条链路

MQTT 客户端向导的作用是：让平台作为 MQTT 客户端连接第三方 Broker，再由 MQTT 接入网关把 Broker 上的设备消息交给平台协议解析。设备不需要直接连接 GPLink，但 Topic 和消息格式必须与协议约定一致。

  • 已知 Broker 域名或 IP、端口和网络连通性
  • 准备好 Broker 用户名和密码（匿名连接可留空）
  • 准备协议、上行 Topic 和设备 ID 规则
  • 确认产品类型为普通直连设备，并准备设备 ID
安全提示：本页截图来自测试环境，页面中的密码仍由输入框遮挡。生产环境请替换为自己的 Broker 参数，不要把密码写入文档或工单。

四步完成配置

1

连接外部 MQTT Broker

在设备管理菜单中进入“MQTT 客户端向导”，第一步选择已有 MQTT_CLIENT 网络组件，或切换到“新建客户端”填写连接参数。

字段填写规则
组件名称对应页面中的“组件名称”，用容易识别的名称，例如“生产 Broker 客户端”。
客户端 ID对应页面中的“客户端 ID”，必须在 Broker 侧唯一；同一个 ID 被多个连接使用会互相踢下线。
Broker 地址/端口分别填写页面中的“Broker 地址”和“Broker 端口”。地址只填域名或 IP，不要写 mqtt://；普通 MQTT 通常使用 1883，TLS 通常使用 8883。本地 EMQX 请填写 127.0.0.1:2883。
用户名/密码对应页面中的“用户名”和“密码”，两项同时填写或同时留空。密码由输入框自动遮挡。
主题前缀对应页面中的“主题前缀”；普通订阅留空，共享订阅可填写类似 $share/gplink 的前缀。
最大消息长度按页面中的“最大消息长度（字节）”填写，必须不小于设备上行消息的实际长度。
TLS/网络证书Broker 要求加密连接时打开页面中的 TLS 开关，并选择已上传的网络证书。
2

绑定 MQTT 接入网关和协议

点击第一步右下角的“下一步”，进入页面中的“MQTT Broker 接入网关与协议”区域。在“配置方式”中选择“选择已有”或“新建接入网关”：选择已有时，从“MQTT 客户端接入网关”下拉框选择绑定当前 MQTT_CLIENT 网络组件的网关；新建时填写“接入网关名称”和“说明”。

在“MQTT 协议”下拉框选择协议，页面下方的“协议主题预览”会显示 Topic、方向、QoS 和说明。上行订阅主题来自协议声明的 MQTT routes，本页面不手工新增 Topic；如果预览为空，需要先补齐协议路由。

3

绑定产品并准备设备

进入“设备产品与设备”区域，分别选择“选择已有”或“新建产品”，以及“选择已有”或“新建设备”。新建产品时填写“产品 ID”和“产品名称”；新建设备时填写“设备 ID”和“设备名称”。

设备 ID 必须符合协议从 Topic 或消息体中解析的设备标识规则，否则消息到达平台后无法匹配设备。页面中的“保存后状态”勾选后会启用网络组件、接入网关、产品和设备；只想保存草稿时可以取消勾选。

4

按顺序保存并完成校验

点击第三步右下角的“下一步”，进入“配置确认与启用校验”。逐项核对页面摘要中的网络组件、Broker、接入网关、协议、产品、设备、主题前缀和保存后启用状态，确认无误后点击右下角“保存并启用”。

保存按“网络组件 → 接入网关 → 产品接入 → 设备”的依赖顺序执行；若中途失败，已经创建成功的资源不会自动删除，需要修正配置后复用或清理这些资源。

保存后如何验证

成功标准：页面提示保存成功，网络组件、接入网关和设备状态为“已启用”，产品的接入方式显示为 MQTT 接入网关。

配置保存成功只说明平台资源已经建立并通过向导校验，不代表外部 Broker 一定已经收到或转发设备消息。还需要使用设备或 MQTT 客户端实际发布协议约定的 Topic 和 payload，再到设备详情、属性或事件页面查看数据。

常见问题

现象优先检查
网络组件启动失败检查 Broker 地址、端口、防火墙和用户名密码；TLS 开启时确认端口和证书匹配。
Client ID 冲突换成 Broker 侧唯一的 Client ID，并确认没有其他平台节点复用该 ID。
协议路由为空确认选择了支持 MQTT 客户端接入的协议，并检查协议是否包含上行 Topic 路由。
设备在线但没有数据逐字符对照 Topic 前缀、产品 ID、设备 ID 和 payload 字段；保存成功不等于消息格式正确。
TLS 握手失败确认 Broker 证书链、域名、端口、TLS 版本以及平台上传的网络证书。
